# Notes for coding agents

Blaster is an action platformer campaign in the spirit of the 8-bit robot
shooters (an intro stage, six robot masters in any order, their weapons, a
three-stage fortress and an ending) built on GameLib
(https://github.com/alonohana627/GameLib, locally `C:\Users\user\GameLib`; a
separate repository). It is the third platformer of GameLib's run
(`GameLib/GAME_SUGGESTIONS/07-blaster.md` is its spec).

## Ground rules

- Consume GameLib only through its CMake targets (`GameLib::core`,
  `GameLib::app`, ...) and public headers (`<gamelib/...>`). Never copy GameLib
  sources into this repository or include its `src/` files. Use what GameLib
  offers (its `FEATURES.md` at the pinned commit) instead of rewriting it.
- GameLib is pinned by full commit hash in `CMakeLists.txt` (`GIT_TAG`,
  `GIT_SHALLOW FALSE`). Bump it only together with a row in
  `docs/GAMELIB_REVISION.md`. GameLib keeps no backwards compatibility.
- GameLib is changed only to fix a bug that blocks the game (GameLib commit
  with a headless test first, then a re-pin). Generic code the game had to
  write itself is kept separable and reported as a P0 candidate for GameLib's
  `FEATURE_SUGGESTIONS.md`; this repository has no feature-suggestions file.
- Snake, Tetris, Pong, Breakout, Asteroids, Invaders, Minesweeper, Leap and
  Bounder are read-only references.
- Every visual is generated by shaders (GameLib's built-in shapes or this
  game's `shaders/`). No image files. Every sound and the music are
  synthesized with GameLib's synth.
- The robot masters, the Overseer and the hero are original characters;
  keep them that way (no trademarked looks or names).
- `src/game` (stages, rules, the session, the demo bot) links only
  `GameLib::core` and `GameLib::ai`: no window, GPU, audio or clock;
  deterministic for the per-tick input. Presentation, menus, sounds and saves
  live in `src/app`.
- **Games have no tests**: no unit tests, no test executables, no
  `GameLib::testing`. The only CTest entry is the template's smoke run
  (`--hidden --require-validation --frames 120`), which enforces zero Vulkan
  validation messages on the title screen.
- Zero compiler warnings, zero shader warnings (glslc `-Werror`), zero
  validation messages.
- Small Conventional Commits (`feat(game):`, `feat(app):`, `fix:`, `build:`,
  `docs:`) after each step that builds and runs. Stage files explicitly;
  never commit build output. Never rewrite history. Push `main` to origin
  after each commit.
- `FEATURES.md` lists what the game does today, verified by running it;
  update it in the same commit as each feature; never list planned work.
- Run the game and look at it after every visual change (GameLib's
  self-test switches plus the `win32-game-window-automation` skill for
  screenshots). Do not drive F11 in automated runs: fullscreen takes over the
  monitor.

## Skill suggestions

Keep `SKILL_SUGGESTIONS.md` up to date: at the start of a session list
`~/.claude/skills/` and move newly installed skills to "Already installed";
add or sharpen an entry (kebab-case name, one paragraph, a "Why") whenever a
task would have gone better with a missing skill. Mention changes in one line.

## Layout

```text
CMakeLists.txt, CMakePresets.json   project, GameLib pin, presets, the smoke run
src/game/   rules -> GameLib::core (+ GameLib::ai for the demo bot)
            rules.*          numbers, the hero's tuning, Input and its text form
            weapons.*        the weapons, their costs and the weakness ring
            stages.*         StageDef/RoomDef, the stage list, the room layout (core::layoutRooms)
            stages_*.cpp     the ten stages, one block of 15 rows per room
            session.*        one attempt: rooms, scrolls (core::RoomScroll), doors, checkpoints,
                             pickups, lifts, warnings, events
            hero.cpp         the hero: controller with slide and ladders, buster charge
                             (core::ChargeMeter), special weapons, conveyors, ice, wind
            enemies.cpp      the twelve enemy kinds and the guardian, spawn points, shields
            bosses.cpp       the six robot masters and the Overseer (StateMachine + PhaseByHealth)
            demo_bot.*       the demo player (ai::bestPlan over a distance map to the next room)
src/app/    presentation -> GameLib::app, ui, fx, ai
            blaster_game.*   the Game: title + demo, stage select, stages, weapon menu, controls,
                             weapon-get scene, game over, ending, HUD
            view.*           the stage: camera (Camera2D locked per room), backdrop, tiles, doors,
                             actors, shots, warnings, weather
            effects.*        flashes, sparks, rings, orbs, debris, dust, shake
            actions.*        the ActionMap (rebindable keys and gamepad), hints with key names
            sounds.*         synthesized effects and fourteen tunes
            profile.*        blaster.ini (settings, key bindings, campaign, statistics)
            palette.*        a core::Palette per theme, the hero's colors per weapon
src/main.cpp                AppConfig and runMain
shaders/    backdrop (sky, far, near, weather per theme), tile, hero, enemy, boss, shot, item
docs/GAMELIB_REVISION.md    the GameLib commit each change was validated with
```

## Stage text

A stage is a list of rooms, each exactly 15 rows of one width (at least 27
columns), attached Right of, Up from or Down from the room before
(`stages.hpp` lists every tile and marker character). The camera is locked
to one room; crossing into the next room scrolls the screen. Rules of thumb
from the controller: a jump rises 3.5 tiles, so a ledge 3 tiles up is the
most; a running jump clears 3 tiles of gap (2 against the wind). Boss doors
('D') sit in the first column of the room behind them. Every exit above the
hero must not be reachable "straight up" through open cells, or the demo
bot's distance map points through a ceiling (close the gap under it).

## Developer aids

- `BLASTER_START_LEVEL=N` (0 intro, 1-6 robot masters, 7-9 fortress): PLAY
  goes straight into stage N with all six weapons; `BLASTER_START_COLUMN=R`
  starts it in room R.
- `BLASTER_REPLAY=<file>`: a recording (`core::InputRecording` text, the
  six-character inputs of `rules.hpp`) drives the stage started with
  `BLASTER_START_LEVEL`. These are GameLib's `app::readDevStart("BLASTER")`.
- `--demo`: the demo bot plays the intro full screen. `--keep-running`: the
  game keeps running without focus, for screenshot scripts.
- F3 shows hitboxes and the session's state.
- Every stage was proven finishable, bosses included, by the demo bot in a
  headless driver kept outside the repository.

## Commands

```powershell
cmake --preset debug           # configure (fetches GameLib from GitHub at the pinned commit)
cmake --build --preset debug
ctest --preset debug           # the smoke run (validation layer required)
build/debug/bin/blaster.exe    # --demo: the demo bot plays the intro full screen
```
